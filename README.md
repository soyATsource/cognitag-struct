# cognitag_struct

日本語の一文を格構造とモダリティに分解し、**LLM を一切使わずに**返答を組み立てる構造層です。

「返答システム」と名乗ると ChatGPT のようなものを想像されますが、そうではありません。
知識ベースを持たないので、知識を要する問いには答えられません。

```
できる    依頼の受領 / 感情の受け止め / 空きスロットの質問 / 理解の言い直し
できない  事実を答える / 説明する / 要約する / 創作する
```

**答えられないことを、答えられないと返します。** これは弱点ではなく設計の意図です。
もっともらしい嘘を作らないために、こういう作りにしてあります。

```
あなた> なぜ空が青いのか
CogniTag> それは私の知識では答えられない。なぜを知る必要がある。
```

そのかわり、返した内容の根拠はすべて追跡できます。

## 根拠が全部見える

`:trace` を有効にすると、入力がどう分解され、どの規則が効いて、なぜその返答になったかが
一行ずつ出ます。以下は実際の出力です。

```
あなた> 行きます
    分割: 行きます(動詞/非自立可能)['POLITE']
    種類: STATEMENT ← 該当なし
    節0: 述語=行く
    補完: GA=話者（丁寧語・主語なし・意志動詞の組み合わせ）
    タグ: #移動
    含意: #移動 → 移動の話 / どこへ、いつなのかが要る
    空きスロット: ['どこに？']
    方針: with_reasoning_gap
CogniTag> 移動の話だな。行き先と時刻で決まるなら、どこへ、いつなのかが要る。どこに？

あなた> 名古屋
    分割: 名古屋(名詞/固有名詞)
    種類: STATEMENT ← 該当なし
    構文: 取れなかった（述語が無い）
    タグ: #場所
    含意: #場所 → 場所の話 / そこが起点か行き先かで意味が変わる
    文脈: 直前の質問への答えとして 名古屋 を受け取った
    方針: answered_with_reasoning
CogniTag> 名古屋に行きます、ということだな。場所の話だな。そこが起点か行き先かで意味が変わる
```

読み方はこうです。

- **分割** — 句辞書での照合と形態素解析の結果。`['POLITE']` は素性
- **種類** — 発話のモダリティ（8 種）と、そう判定した根拠
- **節** — 述語と格スロット。`GA` `WO` `NI` `KARA` `TIME`
- **補完** — 明示されていないが埋めたスロットと、その理由
- **タグ / 含意** — `frames.jsonl` の述語タグと、`reasoning.toml` が引いた含意
- **空きスロット** — フレームが必須としているのに埋まっていないもの
- **方針** — どの応答の型を選んだか

「なぜ空が青いのか」の場合はこうなります。答えられないと判断した理由まで出ます。

```
    分割: なぜ(副詞) | 空(名詞/普通名詞) | が(助詞/格助詞) | 青い(形容詞/一般) | の(助詞/準体助詞) | か(助詞/終助詞)
    種類: Q_OPEN ← 終助詞: か + 疑問詞['なぜ']
    節0: 述語=青い GA=空 ['#質問']
    タグ: #質問
    方針: q_open
```

## 対話の例

```
あなた> おはよう
CogniTag> やあ。

あなた> 手伝ってほしい
CogniTag> そうしたいのだな。

あなた> 明日までにやらないといけないかな
CogniTag> かもしれないな。時の話だな。いつなのかで段取りが変わる

あなた> つらい
CogniTag> しんどい話だな。正論より先に、そう感じたことを認めたい

あなた> 疲れた
CogniTag> しんどい話だな。正論より先に、そう感じたことを認めたい。疲れだな。休息が足りていないなら、無理をしない方がいい
```

`:say` を使うと、理解した内容を 4 段階の詳しさで言い直します。何を保留したかも出ます。

```
あなた> :say 明日は名古屋に行きません
  0: 名古屋に行きません   保留={'topic': ['明日']}
  1: 名古屋に行きません   保留={'topic': ['明日']}
  2: 明日は名古屋に行きません
  3: 明日は名古屋に行きません
```

## 必要なもの

- Python 3.11 以上（標準ライブラリの `tomllib` を使います）
- SudachiPy と SudachiDict-core（`pip` が一緒に入れます）

LLM も、GPU も、ネットワークも要りません。

### 動作確認済みのバージョン

```

```


## 使い方

### 対話してみる

```bash
python chat.py
```

```
:trace   解析の内訳を表示する / しない を切り替える
:say     入力を言い直す（verbosity 0〜3 を並べる）
:help    説明
:quit    終了
```

引数を付けて呼ぶと 1 回だけ答えて終わります。

```bash
python chat.py 名古屋に行きます
```

### 他のプログラムから使う

`pip install -e .` を一度やっておけば、パスも URL も設定ファイルも要りません。

```python
from cognitag_struct import CogniTag

ct = CogniTag()
a = ct.analyze("どこに行きますか")

a.modality.modality   # <Modality.Q_OPEN: 'Q_OPEN'>
a.needs_knowledge     # True  → LLM へ回す判断に使える
a.questions()         # ['どこに？']
a.coverage_note()     # 'Q_OPEN / 解析済 / 節1 / 質問1 / #移動 #質問'
```

構造が取れたかどうかは `parsed` で見ます。例外は投げません。

```python
b = ct.analyze("明日は名古屋に行きません")
b.parsed                      # True
b.ir.clauses[0].slots         # {'NI': Token(surface='名古屋', ...)}
ct.say("明日は名古屋に行きません", verbosity=2)   # '明日は名古屋に行きません'
```

モダリティだけ知りたいときは構文解析を走らせない近道があります。

```python
ct.modality_of("手伝ってほしい").modality   # <Modality.DESIRE: 'DESIRE'>
```

モダリティは 8 種です。どんな入力にも必ず付きます（辞書にも構文解析にも依存しないため）。

```
GREETING / REQUEST / VOLITION / SPECULATION / Q_OPEN / Q_YESNO / DESIRE / STATEMENT
```

`needs_knowledge` が真なら「この問いは構造だけでは答えられない」という意味です。
LLM と併用する構成では、ここを分岐点にできます。

### HTTP を挟んでいない理由

構造層の処理は 0.1 ミリ秒級で終わるので、HTTP の往復（1 ミリ秒以上）の方が支配的に
なってしまいます。同一プロセスで呼ぶ方が速く、依存も少なく、サーバの起動忘れも起きません。
姉妹プロジェクトの語彙辞書（19.6MB）は常駐が要るので API を持っていますが、
こちらは方式を変えてあります。

### テスト

```bash
pip install -e ".[dev]"
cd ..
python -m pytest cognitag_struct/tests -q     # 272 passed
```

**親ディレクトリから実行してください。** パッケージ内から `python -m pytest` を走らせると、

## 設計の柱

### 分類は木構造にしない

カテゴリを `form × content` の 2 軸の交差で表します。

```
form     ことわざ / 慣用句 / 四字熟語 / 固有名詞 / 一般語
content  失敗 / 幸運 / 無駄 / 努力 / 移動 / 場所 / 状態
```

木にすると経路の順序が固定されます。「ことわざ→失敗」と「失敗→ことわざ」の両方から
辿れるようにするには二重登録が要ります。集合の積なら可換性から両方向が保証されるので、
登録は 1 回で済みます。**3 本目の軸は足しません。** 足したくなった区別は
`presupposition`（前提条件）で表します。

### カテゴリは粗いままにする

「豚に真珠」「猫に小判」「馬の耳に念仏」は厳密には意味がずれますが、同じ
`(ことわざ × 無駄)` に入れます。候補を数件に絞るのがカテゴリ層の役割で、そこから 1 件を
選ぶのは Facet（4 軸の数値）の仕事です。細かく分けると分類体系が管理不能になります。

### 句照合を形態素分割より先に

「河童の川流れ」は形態素解析にかけると 3 つに割れます。割ってから再結合すると候補が
組み合わせで増えるので、**先に句辞書で最長一致を取り、残った区間だけを形態素解析へ回します。**

### 素性は 3 つだけ

`POLITE / NEGATIVE / PAST` は命題の内容を変えないので素性で吸収します。
可能・受身・使役・条件は意味を変えるので、別の見出し語か独立したトークンにします。
「行けません」の見出し語は「行く」ではなく「行ける」です。

### 3 節以上は解釈しない

規則ベースは節の組合せで破綻します。上限を設けて、超えたら例外ではなく戻り値
（`Unparsable`）で返します。呼び出し側が通常の分岐として書けるようにするためです。

### 文言をコードに書かない

質問文・応答の型・含意はすべて `data/*.toml` にあります。口調や返し方を変えたければ
データだけ直せば済みます。

### 返答はタグ経由で決める

述語ごとに返答を書くと 136 通り必要になります。あいだにタグ（`#疲労` `#移動` …）を挟めば、
含意は 26 通りで足ります。`frames.jsonl` の述語にタグを 1 つ足すだけで返答が付きます。

## 中身

```
chat.py       対話の入口。Responder が応答方針を決める
facade.py     CogniTag クラス。他のプログラムはここだけ見ればよい

tokenizer.py      句照合 → 形態素分割。サ変動詞と〜てるを畳む
phrase_dict.py    「河童の川流れ」を 1 語として扱う（最長一致）
category_dict.py  2 軸カテゴリの検索
ir.py             Token / Clause / IR の型定義
parse.py          格構造。が/を/に を振り分け、は は topic へ
modality.py       文末から発話の種類を決める。辞書に依存しない
frames.py         述語ごとの必須スロット
gap.py            空きスロットの検出と質問生成
reasoning.py      タグの収集と含意の参照
context.py        会話の文脈。直前の質問への答えを受け取る
generate.py       verbosity 0〜3 の段階生成
select.py         候補から Facet 4 軸で 1 件選ぶ
idiom.py          前提条件を満たす慣用句だけを選ぶ
```

データは 6 ファイルで、どれか 1 つでも欠けると起動しません。

```
data/axes.jsonl              2 軸の定義（form 5 値 / content 7 値）
data/phrases.jsonl           句辞書 13 件
data/frames.jsonl            述語 136 語（必須スロット + タグ）
data/questions.toml          空きスロットを尋ねる文
data/generation_style.toml   文の組み立て方 + 応答の型
data/reasoning.toml          タグ → 含意 26 件
```

Python 16 ファイル・約 3,200 行、テスト 272 件です。

## 正直に書いておくこと

- **試作段階です。** 実務利用を想定した品質保証はしていません
- **フレームは 136 語しかありません。** ここに無い述語は必須スロットの検出ができず、
  「どこに？」のような問い返しが出ません
- **句辞書は 13 件しかありません。** ことわざ・慣用句の照合はほぼ効きません
- **名詞の意味タグが薄いです。** `#場所` 程度の粗さで止まっています。
  語彙辞書（11,980 語）との接続はまだ済んでいません
- **返答は粗いです。** 同じ入力には必ず同じ返答を返します。検証にはこの方が
  都合が良いのですが、対話としては機械的に感じられます
- **2 節までです。** 3 節以上の文は解釈せず `Unparsable` を返します
- **Windows でしか動作確認していません。** OS 依存の処理は入れていないつもりですが、
  Linux / macOS では確かめていません

## CogniTag の全体像

CogniTag は 2 つのリポジトリに分かれています。依存も成熟度も違うためです。

| | 中身 | |
|---|---|---|
| [cognitag-v2](https://github.com/soyATsource/cognitag-v2) | 語彙辞書 11,980 語 × 5 軸。文章をスコアリングする API | 別リポジトリ |
| **cognitag_struct** | 構造層。格解析・モダリティ判定・応答生成 | ここ |

**このリポジトリは語彙辞書を参照しません。** 単体で動くので、19.6MB の辞書を落とさずに
構造層だけを試せます。
