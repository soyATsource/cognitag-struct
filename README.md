# cognitag_struct

日本語の一文を格構造とモダリティに分解し、**LLM を一切使わずに**返答を組み立てる構造層です。

「対話エンジン」と名乗ると ChatGPT のようなものを想像されますが、そうではありません。
知識ベースを持たないので、知識を要する問いにはほとんど答えられません。

```
できる    受け止め / 問い返し / 提案 / 自分についての説明 / 理解の言い直し
できない  事実を答える / 説明する / 要約する / 創作する
```

**答えられないことを、答えられないと返します。** これは弱点ではなく設計の意図です。
もっともらしい嘘を作らないために、こういう作りにしてあります。

```
あなた> なぜ海は青いの
CogniTag> ごめん、なぜは私には分からない。
```

そのかわり、返した内容の根拠はすべて追跡できます。

## 根拠が全部見える

`:trace` を有効にすると、入力がどう分解され、どの規則が効いて、なぜその返答になったかが
一行ずつ出ます。以下は実際の出力です。

```
あなた> 疲れた
    分割: 疲れた(動詞/一般)['PAST']
    種類: STATEMENT ← 該当なし
    節0: 述語=疲れる
    補完: GA=話者（丁寧語・主語なし・意志動詞の組み合わせ）
    タグ: #つらさ #感情 #疲労 #過去
    含意: #疲労 → 疲れ / 無理をしない方がいい
    含意（返答には出さない）: 疲れだな。休息が足りていないなら、無理をしない方がいい
    方針: ack_suggest
CogniTag> お疲れさま。今日はもう休もう。
```

読み方はこうです。

- **分割** — 句照合と形態素解析の結果。`['PAST']` は素性
- **種類** — 発話のモダリティ（8 種）と、そう判定した根拠
- **節** — 述語と格スロット。`GA` `WO` `NI` `KARA` `TIME`
- **補完** — 明示されていないが埋めたスロットと、その理由
- **タグ** — 述語・名詞・文型・素性の 4 系統から集めたもの
- **含意** — タグから引いた「だからどうなのか」。**返答には出さず、ここにだけ残す**
- **方針** — どの型で返したか

辞書を引いた語には、どのエントリに当たったかも出ます。

```
あなた> 資料を作りました
    カテゴリ辞書: 資料[work_050]
    節0: 述語=作る WO=資料
    タグ: #作業 #仕事 #過去
    方針: ack_specify
CogniTag> そうなんだ。どんな資料？
```

## 対話の例

```
あなた> またね
CogniTag> また、明日！

あなた> 腹が立つ
CogniTag> 落ち着いて。少し時間を置こう。

あなた> 休みたい
CogniTag> そうなんだ。一旦休憩しよう。

あなた> 行きます
CogniTag> そうなんだ。どこに？

あなた> 名古屋
CogniTag> 名古屋に行きます、ということだね。

あなた> 君は誰
CogniTag> 私は CogniTag。辞書と構文だけで日本語を組み立てる仕組みだよ。

あなた> さっき何て言った
CogniTag> 「私は CogniTag。辞書と構文だけで日本語を組み立てる仕組みだよ。」って言ったよ。
```

## 返答の作り方

**固定文を並べていません。** 持っているのは「単語」「助詞」「述語」の並び（文型）だけです。

```jsonl
{"id": "confirm_wo", "need": ["WO"], "elements": ["WO", "を", "PRED"], "spec": {"mood": "confirm"}}
```

`WO` に相手の語が入り、`PRED` は活用させて埋めます。1 つの入力から複数の候補が出ます。

```
鍵をなくした → 鍵をなくしたんだね / なくしたんだね / なくしたの？
              / なくしただろうね / 鍵をなくしたの？ / 鍵をなくしましたか …
```

**この候補はどこにも書いてありません。** 文型 22 本 × 埋まっている格 × 活用の組み合わせで
出てきます。文型を 1 本足すと、条件を満たす全入力に効きます。

述語の活用は表（`data/conjugation.toml`）から作ります。

```
行く  → 行く / 行った / 行かない / 行きますか / 行ったんだね / 行こう / 行きませんでした
高い  → 高い / 高かった / 高くない / 高いですか / 高かったんだね
```

**乱数は使いません。** 同じ会話を最初からやり直せば同じ結果になります。会話の中で
言い方が変わるのは「その型を何回目に使ったか」で選んでいるためです。

## 知らないことを知っている

被覆率と未知語を出せます。**知らない語を隠しません。**

```python
a = ct.analyze("ロルカナのデッキを組んだ")
a.coverage        # 0.0
a.unknown_words() # ['ロルカナ', 'デッキ', '組む']
```

辞書に無い語ばかりでも、構造からは返せます。

```
あなた> ロルカナのデッキを組んだ
CogniTag> デッキを組んだんだね
```

対象のテキストに対する被覆率を測れます。**語数は在庫の話であって性能ではない**ので、
実際の文章で何割を説明できたかで見ます。

```bash
python -X utf8 eval/coverage.py --cases
python -X utf8 eval/coverage.py --corpus <テキストの入った場所>
```

```
内容語        260
辞書にある    149   57.3%
未知と申告    111   42.7%
```

未知語は必ず一覧で出します。「知っているはずなのに未知になっている」語を
目で見つけるためです。

## 必要なもの

- Python 3.11 以上（標準ライブラリの `tomllib` を使います）
- SudachiPy と SudachiDict-core（`pip` が一緒に入れます）

LLM も、GPU も、ネットワークも要りません。

## 使い方

### 対話してみる

```bash
python chat.py
```

```
:trace   解析の内訳を表示する / しない を切り替える
:say     入力を言い直す（verbosity 0〜3 を並べる）
:help    説明
:quit    終了
```

### 配信などに映す画面

```bash
python stream_gui.py
```

左に会話、右に判断の内訳が出ます。Tkinter（標準ライブラリ）なので依存は増えません。
`F1` で内訳の表示、`F2/F3` で字の大きさを切り替えられます。

### 他のプログラムから使う

```python
from cognitag_struct import CogniTag

ct = CogniTag()
a = ct.analyze("どこに行きますか")

a.modality.modality   # <Modality.Q_OPEN: 'Q_OPEN'>
a.needs_knowledge     # True  → LLM へ回す判断に使える
a.questions()         # ['どこに？']
a.coverage            # 1.0
a.unknown_words()     # []
```

構造が取れたかどうかは `parsed` で見ます。例外は投げません。

```python
b = ct.analyze("明日は名古屋に行きません")
b.parsed                      # True
b.ir.clauses[0].slots         # {'NI': Token(surface='名古屋', ...)}
ct.say("明日は名古屋に行きません", verbosity=2)   # '明日は名古屋に行きません'
```

モダリティは 8 種で、どんな入力にも必ず付きます（辞書にも構文解析にも依存しないため）。

```
GREETING / REQUEST / VOLITION / SPECULATION / Q_OPEN / Q_YESNO / DESIRE / STATEMENT
```

### 外の世界を触る

天気・時刻・Blender の操作を差し込めます。**既定では何も繋がっていません。**

```bash
python chat.py --with=clock,weather
```

```
今何時ですか   → 15 時 39 分だ。
明日は雨ですか  → 予報では、明日の東京は雨。最高 27.6 度、最低 23.8 度だ。
立方体を作って  → 立方体を作って cube.blend に保存した。
```

差し込まないかぎり、返答は辞書と構文だけから決まります（単体で動くことと決定性を
崩さないため）。外から来た値には出どころの印が付き、`:trace` に必ず出ます。

## 設計の柱

### 分類は木構造にしない

カテゴリを `form × content` の 2 軸の交差で表します。

```
form     ことわざ / 慣用句 / 四字熟語 / 固有名詞 / 一般語
content  失敗 / 幸運 / 無駄 / 場所 / 人物 / 健康 / 食事 / 仕事 …（31 値）
```

木にすると経路の順序が固定されます。「ことわざ→失敗」と「失敗→ことわざ」の両方から
辿れるようにするには二重登録が要りますが、集合の積なら可換性から両方向が保証されます。
**3 本目の軸は足しません。** 足したくなった区別は `presupposition`（前提条件）で表します。

### 句照合を形態素分割より先に、ただし 1 形態素の語は除く

「河童の川流れ」は形態素解析にかけると 3 つに割れます。割ってから再結合すると候補が
組み合わせで増えるので、**先に句辞書で最長一致を取ります。**

ただし 1 形態素で済む語は句照合に載せません。句照合は境界を見ないので、「会社」を
句として登録すると「会社員です」が 会社 + 員です に割れて壊れます。**再結合の問題が
あるのは複数形態素の句だけ**なので、1 形態素の語は分割の後に見出し語で引きます。

### 説明を返さない

タグから引いた含意（「移動の話だな。行き先と時刻で決まるなら…」）は、**システムが
何を考えたかであって、相手に言うことではありませんでした。** 返答には受け止めの一句と
問い返しだけを出し、含意は `:trace` に残します。

### 素性は 3 つだけ

`POLITE / NEGATIVE / PAST` は命題の内容を変えないので素性で吸収します。
可能・受身・使役は意味を変えるので、別の見出し語か独立したトークンにします。
「行けません」の見出し語は「行く」ではなく「行ける」です。

### 3 節以上は解釈しない

規則ベースは節の組合せで破綻します。上限を設けて、超えたら例外ではなく戻り値
（`Unparsable`）で返します。呼び出し側が通常の分岐として書けるようにするためです。

### 文言をコードに書かない

質問文・応答の型・含意・活用表・文型はすべて `data/` にあります。口調や返し方を
変えたければデータだけ直せば済みます。

### 知識と自己記述を分ける

「富士山の高さ」は世界についての知識で、持とうとすると際限がありません。
「自分が何であるか」は有限で、しかも書いた本人が正しい。**世界を知らないまま
自分については答えられる**、という線を引いています（`data/self.toml`）。

事実の表（`data/facts.jsonl`）も持っていますが、百科事典ではありません。何度も
聞かれるものだけを 6 件置いてあり、載っていないことは今までどおり分からないと返します。

## 中身

```
chat.py       対話の入口。Responder が応答方針を決める
facade.py     CogniTag クラス。他のプログラムはここだけ見ればよい
stream_gui.py 配信などに映す画面

tokenizer.py      句照合 → 形態素分割。サ変動詞と〜てるを畳む
phrase_dict.py    「河童の川流れ」を 1 語として扱う（最長一致）
category_dict.py  2 軸カテゴリの検索
ir.py             Token / Clause / IR の型定義
parse.py          格構造。が/を/に を格へ、は は topic へ。名詞述語も扱う
modality.py       文末から発話の種類を決める。辞書に依存しない
frames.py         述語ごとの必須スロットと、格が期待するカテゴリ
gap.py            空きスロットの検出と質問生成
reasoning.py      タグの収集と含意の参照
context.py        会話の文脈。直前の質問・話題・発話そのもの
inflect.py        述語の活用。行く → 行きますか / 行ったんだね
compose.py        文型に単語を埋める。空いた格には辞書から 1 語引く
generate.py       verbosity 0〜3 の段階生成
select.py         候補から Facet 4 軸で 1 件（valence は距離に入れない）
idiom.py          前提条件を満たす慣用句だけを選ぶ
selfdesc.py       自分について答える
facts.py          用意してある事実に答える
capability.py     外の世界を触る差し込み口
providers/        時計・天気・Blender（既定では差し込まれない）
```

データ。どれか 1 つでも欠けると起動しません。

```
data/axes.jsonl              2 軸の定義（form 5 値 / content 31 値）
data/phrases.jsonl           カテゴリ辞書 525 件
data/frames.jsonl            述語 140 語（必須スロット + タグ + 期待カテゴリ）
data/questions.toml          空きスロットを尋ねる文
data/generation_style.toml   応答の型と口調
data/reasoning.toml          タグ → 受け止め / 提案 / 含意（36 件）
data/conjugation.toml        活用表
data/patterns.jsonl          返答の文型 22 件
data/self.toml               自分について
data/facts.jsonl             用意してある事実 6 件
```

Python 22 ファイル・約 5,400 行、テスト 335 件です。

## 正直に書いておくこと

- **試作段階です。** 実務利用を想定した品質保証はしていません
- **述語のフレームは 140 語です。** ここに無い述語では必須スロットの検出ができず、
  品詞と構造からの一般規則で返します
- **カテゴリ辞書 525 語のうち、日常語は 3 割ほどです。** 残りは語彙辞書から採った
  専門用語で、会話ではあまり出てきません。専門的な解説文 1,070 文で測ったときの
  被覆率は 11.9%、構造が取れた文は 37.9% でした。会話文ならもっと高くなりますが、
  **日常語の基盤がまだ薄い**のは確かです
- **ことわざは 10 件です。** 仕組みはありますが弾がありません
- **2 節までです。** 3 節以上の文は解釈せず `Unparsable` を返します
- **Windows でしか動作確認していません。** OS 依存の処理は入れていないつもりですが、
  Linux / macOS では確かめていません

## CogniTag の全体像

CogniTag は 2 つのリポジトリに分かれています。依存も成熟度も違うためです。

| | 中身 | |
|---|---|---|
| [cognitag-v2](https://github.com/soyATsource/cognitag-v2) | 語彙辞書 11,980 語 × 5 軸。文章をスコアリングする API | 別リポジトリ |
| **cognitag_struct** | 構造層。格解析・モダリティ判定・応答生成 | ここ |

**このリポジトリは実行時に語彙辞書を参照しません。** 単体で動くので、19.6MB の辞書を
落とさずに構造層だけを試せます（辞書は語彙を作るときの入力としてだけ使いました）。
